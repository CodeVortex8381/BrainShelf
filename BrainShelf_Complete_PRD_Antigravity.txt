BRAINSHELF — COMPLETE PRODUCT REQUIREMENTS DOCUMENT
Version 2.0 | 15 October 2026
A Student Notes Sharing Platform | Antigravity implementation brief

1. EXECUTIVE SUMMARY
BrainShelf is a responsive web platform where students discover, upload, organize, share, and download academic notes. Student PDF uploads stay pending until an administrator reviews them. Only approved notes are public.
Tagline: Learn together. Grow together.

5. ROLES
Visitor: browse/search approved notes; cannot upload or use admin features.
Student: register/login/logout, upload PDFs, view own statuses, download approved notes.
Admin: protected moderation dashboard, review queue, approve/reject/delete notes, see database-backed statistics. Public registration must never grant admin role.
Out of scope: payments, chat, social feed, ratings/comments, AI summaries, native mobile app, SSO, complex multi-college permissions.

10. DATA MODELS
User: name, normalized unique email, passwordHash, optional semester/college, role (student/admin; default student), timestamps. Never serialize passwordHash. Public registration must reject/ignore role=admin.
Note: title, subject, category, semester, description, optional tags, uploader, status (pending/approved/rejected), optional rejectionReason, storageProvider, storagePublicId, secureUrl, fileSizeBytes, sanitized originalFileName, timestamps, reviewedBy, reviewedAt. Add appropriate indexes and validation.

11. API CONTRACT
GET /api/health — safe health/config status
POST /api/auth/register — create student
POST /api/auth/login — authenticate
POST /api/auth/logout — clear session/cookie
GET /api/auth/me — current user, no sensitive fields
GET /api/notes — approved list; query/category/semester/page/limit
GET /api/notes/:id — approved detail
POST /api/notes — authenticated PDF upload
GET /api/notes/mine — student's uploads/statuses
GET /api/notes/:id/download — authorized approved download
GET /api/admin/notes?status=pending — admin queue
PATCH /api/admin/notes/:id/review — admin approve/reject with optional reason
DELETE /api/admin/notes/:id — admin delete and storage cleanup
GET /api/admin/stats — admin counts
Use suitable HTTP status codes: 400, 401, 403, 404, 409, 413, 415, 429, 500.

13. SECURITY
- Validate all inputs server-side; allowlist status/category/semester/sort and pagination.
- Authenticate and authorize every protected endpoint; hiding buttons is not security.
- Rate-limit login/registration.
- Configure CORS for known origins; no wildcard with credentialed cookies.
- Use Helmet or equivalent security headers.
- Never trust client-supplied user IDs, roles, status, URLs, or filenames.
- Students cannot approve their own notes or modify another user's notes.
- Pending/rejected files are not public downloads.
- Use HTTPS in production and safe storage cleanup.
- Never log secrets or expose stack traces/provider internals.
